An unbiased sample of the mutants of changes already landed, out of the loop: how a person sees whether the agents' picks lean toward what their tests already hold.

The agent that makes a change picks its mutants (see [mutants scope](help:mutants-scope)), so its picks may be the ones its tests catch. `slimfit next --sample <N>` draws mutants nobody chose and runs them, and `slimfit report` sets their survival beside the picks'. If the two rates part far, the picks are biased; what to do then is a person's decision, not slimfit's.

- **What it draws from**: the source lines HEAD's history added since the last sample committed in `.slimfit/samples/` (its `tip`), or, before any, since the first-parent commit {const:SAMPLE_DAYS} days back; never from before the baseline's `mutants_from`. Of the mutants the suite's tool lists of those lines, a name a record in `.slimfit/mutants/` added since then picked is left out, wherever an edit has since moved it.
- **The draw**: uniform, by a generator seeded by HEAD's commit alone, so the same tip always draws the same mutants: nobody can draw again for a better result. It runs N of them as picks run (each with the tests that ran its function, under the same timeouts); a drawn mutant that does not build is replaced by the next in the draw, in at most {const:SAMPLE_ROUNDS} runs. The run is cached in `.slimfit/out/` per tip and N.
- **What it answers**: in `next`'s task format, each survivor as a `surviving-mutant` task whose `evidence.source` is `sampled` (a pick's is `picker`), and, when it drew any, a `record-sample` task: the sample, {const:SAMPLE}, to write to `.slimfit/samples/<tip>.json` and commit. `notes` sums it up.
- **Out of the loop**: no `check` or `ratchet` reads a sample, and no record's verdict is re-decided. A sampled survivor is a task, never a bound: `check` stays green with it outstanding. Nor is it the worker's: it runs where nothing else waits, on factorium's idle tasks line (`tasks = "slimfit --version && slimfit next --all --sample 5"`, see [setting up in factorium](help:factorium)), which files each kind's first task as an issue.
- **What it costs**: the mutation tool's first build, plus a build and a test run per drawn mutant, at the priority it runs at (the idle tasks line's is background). Measured on slimfit itself: {const:SAMPLE_COST}.
- **What report shows**: each `history` point's `mutants_survival`, per source (`picker`, a second agent's picks; `author`, picks in records that name no other picker; `sampled`), over the records and samples committed by then: {const:RATE}.
